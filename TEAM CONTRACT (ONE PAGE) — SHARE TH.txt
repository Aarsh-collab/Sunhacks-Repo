Enums (don't invent new values)
    •    Listing.status: active | pending_meetup | meetup_set | sold | flagged
    •    Meetup.status: proposed | accepted | completed | cancelled
    •    Meetup.spot: Hayden Library Lobby | MU Starbucks | Student Services Lawn | Polytechnic Student Union Desk

Normalization rules
    •    createdAt: number (ms) from Date.now()
    •    price: number
    •    courseCodes: array of strings like ["MAT265","CSE110"]
    •    searchKeys: UPPERCASE tokens only (title words, author, course codes, ISBN)

QUERIES & INDEXES (EVERYONE RELIES ON THIS)
    •    Feed query: where status == "active" orderBy createdAt desc (limit 100)
→ Composite Index required: status (ASC), createdAt (DESC)

COMMON SERVICE SHAPES (NAMES + PARAMS)

Even if you all write your own files, stick to these function names/signatures so pages can call them the same way.

Listings

// returns latest active listings; client may further filter
queryListings(filters?: { course?: string; min?: number; max?: number; text?: string }): Promise<Listing[]>

getListing(id: string): Promise<Listing>

createListing(input: {
  ownerUid: string; title: string;
  author?: string; isbn?: string; edition?: string;
  courseCodes: string[]; price: number; imageUrl: string;
  searchKeys: string[];               // UPPERCASE tokens
}): Promise<string>                   // returns new listing id

setListingStatus(id: string, status: ListingStatus): Promise<void>

Meetups

proposeMeetup(input: {
  listingId: string; buyerUid: string; sellerUid: string;
  spot: MeetupSpot; timeISO: string;
}): Promise<string>

acceptMeetup(id: string): Promise<void>

completeMeetup(id: string): Promise<void>  // also set listing.status='sold' and increment seller.reputation.completedTrades

Users

getUser(uid: string): Promise<User>
ensureUserDoc(): Promise<void>

Messages

sendMessage(input: {
  listingId: string; fromUid: string; toUid: string; text: string;
}): Promise<string>                    // returns new message id

fetchThread(input: {
  listingId: string; uidA: string; uidB: string;
}): Promise<Message[]>                 // returns messages in chronological order

getUserConversations(uid: string): Promise<Conversation[]>  // returns user's conversation summaries

PAGE CONTRACTS (WHAT EACH PAGE CAN EXPECT)

Feed (feed.html / main screen)
    •    Calls: queryListings({ course?, min?, max?, text? })
    •    Shows: cards with imageUrl, title, courseCodes, price, seller name/email (from users)
    •    Clicking card → listing.html?id=<listingId>

Listing Detail (listing.html)
    •    Reads query param id
    •    Calls: getListing(id)
    •    Buttons:
    •    "Message Seller" → redirects to messages.html with listing context
    •    "Propose meetup" → opens modal → calls proposeMeetup(...)

New Listing (new.html)
    •    Form fields: title*, author, isbn, edition, courseCodes (comma or chips), price*, image*
    •    On submit:
    1.    compress + upload image → get imageUrl
    2.    build searchKeys (uppercase tokens)
    3.    call createListing(...) → redirect to listing.html?id=<newId>

Messages (messages.html)
    •    Calls: getUserConversations(uid)
    •    Shows: list of conversation threads with last message preview
    •    Clicking thread → fetchThread({ listingId, uidA, uidB })
    •    Send message → sendMessage({ listingId, fromUid, toUid, text })

Meetups (meetups.html)
    •    Two tabs: Buyer and Seller (filter by current user)
    •    Buttons:
    •    Seller: Accept → acceptMeetup(id) + set listing to meetup_set
    •    Both: Mark Completed → completeMeetup(id) (sets listing sold, bumps seller completedTrades)

⸻

ERROR / EDGE BEHAVIOR
    •    If listing not found → show “Listing not found” with link back to feed.
    •    If user doc missing → call ensureUserDoc() quietly in background after login.
    •    If email missing → disable “Contact Seller” button (opacity: .5; pointer-events: none).
